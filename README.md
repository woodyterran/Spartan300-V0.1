# Spartan300 V0.1

Spartan300-V1 的简易采集版：面向专家高技能手工劳动视频采集，用于机器人训练。沿用 V1 的 DeepReach 品牌、米白底色（#fffaf3）、陶土橙（#bd4f24）、深棕文字（#302b26）和绿色收益状态；直接复用 V1 的专家及手艺配图。Mac 本地移动端 H5 交互原型，无第三方依赖。需要 Node.js 20 或以上版本。

当前版本：`v0.1.0`。完整功能、更新内容、运行方式与实现边界见 [版本说明](CHANGELOG.md)。

## 启动

首次从 GitHub 获取代码：

```sh
git clone https://github.com/woodyterran/Spartan300-V0.1.git
cd Spartan300-V0.1
npm run dev
```

本项目无第三方运行依赖，不需要安装额外 npm 包。本机已有项目时也可直接启动：

```sh
cd /Users/wanlong/Documents/ChatGPT/Spartan300-V0.1
npm run dev
```

服务器监听 `0.0.0.0:3000`，启动时通过 macOS `networksetup` 找到 Wi-Fi 网卡，再用 `ipconfig getifaddr` 查询真实 IPv4。终端打印 Local 与 Wi-Fi URL；无法确认 Wi-Fi 时会标明为未验证网络地址，不虚构地址。端口占用时报告错误，不停止其他进程。

手机与 Mac 连接同一 Wi-Fi，用终端打印的 Wi-Fi URL 访问。Mac 保持运行且服务器不退出。如果访问失败，检查 macOS 是否允许 Node 的入站连接、是否使用访客网络，以及路由器是否启用设备隔离。无需连接任何云服务。

- `/`：PC 仅展示公开首页；手机继续使用原有 H5 流程。
- `/preview.html`：旧预览入口，现跳转首页；不能通过缩小窗口或 iframe 在 PC 使用采集功能。
- `/admin`：配套 PC 结算管理后台。
- `/api/health`：只读服务状态与当前 Wi-Fi 地址。

## 在 GitHub Codespaces 中继续开发

1. 在 GitHub 仓库选择 `codex/dev-2026-10-31` 分支，再打开 **Code → Codespaces → Create codespace on codex/dev-2026-10-31**。
2. 环境使用 Node.js 22，首次创建会执行语法检查与测试，启动后自动运行开发服务。
3. 在编辑器底部 **Ports（端口）** 中打开 `3000` 的转发地址。保持端口为 **Private**；手机扫码后需在浏览器登录创建 Codespace 的同一 GitHub 账号，无需与 Mac 连接同一 Wi-Fi。
4. 编辑代码后，在云端终端停止旧服务并重新运行 `npm run dev`；提交并推送代码后，其他电脑才能通过 GitHub 获取这些改动。

云端地址依据 GitHub 提供的 `CODESPACE_NAME` 与 `GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN` 自动生成；登录及二维码均支持当前 Codespace 的 HTTPS 地址。本地 Mac 仍使用原有局域网流程。真实摄像头还取决于手机浏览器权限与设备支持，请在手机浏览器直接打开预览地址。

如果预览没有启动，查看 `/tmp/spartan300-dev.log`，或在终端运行 `npm run dev`。默认自动启动不包含文件热更新；重启服务后刷新页面查看修改。

`.data/`、截图与本地视频均不随 Git 同步。新 Codespace 默认初始化独立演示数据，Mac 原有数据保留。需沿用旧账号与结算记录时，单独备份并传入 `.data/store.json`，在服务停止时替换，勿将其提交到 GitHub。Codespace 内的 `.data/` 位于项目目录，删除 Codespace 前须单独备份；浏览器里的真实视频需在原浏览器导出。

Codespaces 是开发环境，停止后预览不可用。用完可在 GitHub Codespaces 页面停止实例；配额和计费以 GitHub 账户页面为准。

## 完整流程

1. 登录，直接输入想展示的具体高技能手艺。
2. 按顾问提示补充工作场景、专业操作工具和拍摄设备，完成三轮模拟对话。
3. 模拟评估通过并由本机服务成功领取后，出现拍摄指导和 6 小时独占倒计时。普通风景内容不符合采集方向；重复手艺、隐私、安全或缺少录音条件的预设关键词会演示拒绝；不是实际内容审核。
4. 进入准备页，选择模拟或真实设备录制。确认横屏与声音要求，点击圆形按钮开始。
5. 录制中不可切换摄像头。结束后预览视频，选择“放弃本次”或“上传（模拟）”；放弃、中断或刷新后可在原 6 小时窗口内重拍，截止时间不重置。
6. 上传由用户主动选择；同一轮领取最多成功提交一条视频。模拟拍摄可切换“模拟断网 / 恢复网络”；选择上传时若仍处于模拟离线，将标记为待补传，实际恢复并模拟提交时仍须在截止时间前。模拟上传成功后显示“请等待审核结果”，不提供用户自行审核或计入收益的入口；收益页面保留预置的演示余额。
7. “我的”中可申请全额演示结算，申请会进入本机 PC 后台；管理员处理前可撤销恢复余额。后台可登记线下付款结果或填写原因退回。处理状态和备注同步到手机端，不会通知外部联系人或发起真实付款。

## 真实实现与模拟边界

| 能力 | 实现 |
| --- | --- |
| 手机号密码登录 / 注册 | 本机服务器认证、加盐密码摘要与 HttpOnly 会话，无短信或真实身份校验 |
| AI 咨询 / 悬赏评估 / 拍摄指导 | 本地规则与预设文案，无 AI 或外部悬赏接口 |
| 语音入口 | 可编辑的模拟转写，无麦克风采集或语音识别 |
| 拍照 / 相册入口 | 原生图片选择器，咨询参考图片仅在本地，不识别、不上传；拒绝视频 |
| 6 小时悬赏独占 | 本机服务器原子领取与到期检查；仅领取人可在截止前开始与提交，重拍不重置窗口；每轮只允许一条模拟提交 |
| 模拟拍摄 | 插画预览、计时与模拟分片，无实际视频数据 |
| 真实录制 | 仅在安全环境且设备支持时，使用 getUserMedia + MediaRecorder 采集摄像头与必需音轨 |
| 规格 | 真实模式要求横屏、实际视频轨 1920 × 1080，规格不满足或无音轨时阻止开始 |
| 摄像头切换 | 仅录制前支持前后偏好切换，实际设备选择由浏览器决定；录制中锁定 |
| 本地分片 | 真实模式以约 5 秒间隔写入 IndexedDB；间隔取决于浏览器，不保证精确 |
| 分片上传 / 断网补传 | 只有模拟状态，没有上传请求、对象存储、上传队列或服务端合并 |
| 回放 / 导出 | 真实本地分片组合为 Blob，提供播放器和下载；浏览器编码兼容性决定是否能播放 |
| 拍摄记录 / 收益 | 采集文件仍在浏览器本地，默认账户预置三条模拟样例；金额均为演示 |
| 结算与用户管理 | 本机 JSON 数据持久化；移动端提交申请、PC 后台处理与账户状态联动，没有支付渠道 |

局域网 **HTTP 的手机网页通常不属于安全环境，不能使用 getUserMedia**。同一 Wi-Fi URL 优先用于完整模拟交互测试。真实摄像头测试需使用 Mac 的 `http://localhost:3000` 或另行配置手机信任的 HTTPS；本项目没有安装证书或绕过浏览器安全限制。

真实录制最长 30 分钟，到时自动停止；切后台、音轨或设备中断会结束录制并保存已收到的分片。浏览器退出、锁屏、系统挂起、存储容量不足时，不能保证完整恢复；页面下次打开会把未完成录制标记为中断，可在仍有效的独占窗口内放弃重拍。请保持前台并及时导出。IndexedDB 可能被浏览器清理。没有生产级持久化、恢复协议或后台上传保证。

## PC 结算管理后台

电脑打开 `http://localhost:3000/admin`，或使用启动时打印的 Wi-Fi 地址后加 `/admin`。

- 管理员账号：`admin`
- 演示密码：`spartan300-admin`
- 可通过 `SPARTAN_ADMIN_PASSWORD` 环境变量替换默认管理员密码。
- 工作台总览：待结算金额、用户概况、近 7 日演示付款登记、最近操作。
- 结算申请：状态筛选、搜索、详情、导出 CSV；管理员确认后登记线下已付款，或填写原因退回。
- 用户管理：搜索、查看资料与余额、修改姓名/手艺/备注、新增演示用户、启用或停用账户、导出 CSV。
- 悬赏管理：独占中、待审核、可领取与已完成列表；模拟判失败并释放或模拟审核通过，保留每一轮领取与提交记录。
- 操作记录：结算与悬赏状态变化、用户修改留痕。

手机端“我的”每约 5 秒刷新一次账户与结算状态，且在弹窗或录制时暂停刷新，避免打断操作。后台每约 15 秒静默刷新一次，编辑表单或查看详情时暂停；也可手动刷新。

全额申请在服务器原子预留余额，重复提交、重复登记和处理后的再次撤销均会被阻止。金额按整数分保存。处理前撤销或管理员退回只恢复一次余额；付款登记只更新记录，不调用银行、微信、支付宝或任何真实支付服务。

运行数据保存在 `.data/store.json`，采用临时文件写入后替换的方式保存，账户密码摘要不通过 API 返回；该目录不对网页开放且已忽略提交。会话保存在服务器内存，服务器重启后可能需要重新登录。请保留 `.data/` 以保留演示业务记录。此系统尚未包含生产级数据库、备份、完整权限体系或 HTTPS 部署。

旧版手机演示数据会在首次接入本机服务时导入一次；原浏览器数据在 `s300-before-server-<手机号>` 保留快照。相同手机号此前在多个浏览器产生的不同演示余额，以首次导入的数据为准，其余浏览器原快照保留；之后以服务器为准，客户端不能反复覆盖管理员处理结果。旧账号可能需要重新登录一次。视频文件不会迁移到服务器。

预置的其他师傅、联系电话、待结算记录与付款登记均为演示数据，没有自动联系任何人。移动端仍保留“模拟上传成功，等待审核”的流程，不会由用户自行点击审核通过计入收益。

## 六小时独占与重拍规则

- 评估通过后，以本机服务器成功领取悬赏的时刻为窗口起点。截止时间由服务器生成，刷新、重复领取、拍摄与放弃均不延长。
- 拍摄结束只保存到本地，尚未提交。放弃后可立即或稍后重拍，也可从顾问页“我的独占任务”继续；独占窗口内其他用户无法领取该任务。
- 用户主动选择上传后，本原型只提交采集记录信息（时长、分片数量、记录编号），**不上传视频文件**。真实录制同样只有本地回放与导出，不存在真实上传通道。
- 以本机服务收到模拟提交信息为成功提交时刻；必须严格早于截止时间。模拟断网缓存、点过上传、尚在录制都不算成功提交。
- 已在窗口内提交成功的任务继续等待审核，超过六小时不会自动释放。后台判失败后立即释放；到期未提交的任务在下一次请求检查时释放。其他用户会在顾问页可领取悬赏中看到释放的任务，需说明场景与工具后重新评估领取。
- 已失效的领取编号、旧草稿和旧管理员页面均不能提交或影响新一轮领取。每轮最多一条有效提交，重复请求不会创建第二条。
- 后台审核只是状态演示，没有视频文件可供真实审查。模拟通过后任务完成，不自动计入收益；模拟失败说明会同步给手机端。
- 悬赏按稳定任务编号区分；新咨询用标准化完整手艺标题创建任务。同义表达的自动合并与真实悬赏库查重仍未实现。
- 领取、任务归属和期限保存在 `.data/store.json`，服务重启后保留。前端每约 10 秒同步任务状态，并用服务器时间计算倒计时；最终期限由服务端判断。

## PC 首页与手机扫码交接

PC 浏览器仅展示项目介绍首页。登录 / 注册、拍摄顾问、拍摄记录、我的及采集入口都会弹出“请用手机扫码继续”，不在 PC 建立用户会话或展示账户数据。设备识别基于浏览器设备标识与 iPad 触摸特征，不以窗口宽度判定；这是一项产品界面限制，不是防伪造的安全认证。

二维码由本机 `/api/mobile-entry` 接口生成，使用每次读取的真实 Wi-Fi IPv4 和服务端口，附带白名单 `continue` 参数。二维码不包含账号、密码或会话，不经第三方二维码服务。手机扫码后进入对应标签；未登录时先登录。Mac 未连接可确认的 Wi-Fi 时显示重试提示，不生成 localhost 或虚构地址。

独立 `/admin` 是专门的 PC 管理后台，不受采集端扫码规则影响。局域网 HTTP 的真实摄像头限制依旧存在。

二维码编码使用本地内置的 [qrcode-generator 2.0.4](https://github.com/kazuhikoarase/qrcode-generator)；源码在 `vendor/qrcode.mjs`，保留原作者版权与 `vendor/qrcode-LICENSE.txt` 的 MIT 授权。无需安装第三方运行依赖或联网加载脚本。
